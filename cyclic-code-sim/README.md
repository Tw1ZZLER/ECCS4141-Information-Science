# (15,11) Cyclic Code Shift-Register Simulator

An interactive terminal simulator for the binary (15,11) cyclic code generated by `g(x) = 1 + x^3 + x^4`. It follows an 11-bit message through a clocked encoder LFSR, an optional single-bit channel error, a clocked syndrome register, lookup-table error location, correction, and message recovery.

The UI is a Vaxis TUI. Flip-flops and XOR taps are drawn with box-drawing characters and update on every clock.

## Run

The project uses Zig 0.16.0 and pins Vaxis 0.6.0 in `build.zig.zon`.

```sh
zig build run
```

The first build needs network access to fetch the pinned Zig dependencies. Later builds use Zig's package cache.

Other useful commands:

```sh
zig build
zig build test
zig fmt --check build.zig src/*.zig
```

The installed executable is `zig-out/bin/cyclic-code-sim`.

## Controls

- Message screen: type eleven `0` or `1` digits (`m0` through `m10`, left to right), `Backspace` to remove one, then `Enter`.
- Clocked screens (encoder, syndrome): `Space`, `n`, or `Right` advances one clock. `Left` or `Backspace` steps backward. `p` plays/pauses at 400 ms per clock. `f` finishes the current 15-clock stage. `Enter` continues once the stage is complete.
- Channel screen: `Left`/`Right` or `h`/`l` choose no error or `c0`–`c14`. `0` selects no error. Click a label with the mouse. `Enter` or `Space` transmits.
- Result screen: `t` opens the automatic test of all 15 single-bit errors.
- Any screen: `r` starts over; `q` or `Ctrl-C` exits.

After every completed stage, the bottom-left performance line reports elapsed time in nanoseconds. Measurements use Zig's monotonic `std.Io.Clock.awake` clock.

The UI switches to a compact layout in a small terminal. A terminal of at least 150 columns by 28 rows shows the shift-register artwork most clearly.

## Convention

All arithmetic is in GF(2), so addition is XOR.

```text
g(x) = 1 + x^3 + x^4
G    = [g0 g1 g2 g3 g4] = [1 0 0 1 1]
```

A message is a row of coefficients `m = [m0 m1 ... m10]`, so `m(x) = m0 + m1 x + ... + m10 x^10`. The systematic codeword is

```text
c(x) = p(x) + x^4 m(x)
c    = (p0 p1 p2 p3 | m0 m1 ... m10)
```

The high-order bit `c14 = m10` is sent first. After the 11 message bits, the four parity bits shift out `p3`, `p2`, `p1`, `p0`.

## Encoder

The encoder is the standard premultiplied-by-`x^(n-k)` division circuit. The message enters at the high end of the four-stage register.

On each of the first 11 clocks the gate is on:

```text
fb = m_i XOR r3
r0' = fb
r1' = r0 XOR g1 fb
r2' = r1 XOR g2 fb
r3' = r2 XOR g3 fb
```

The systematic output during those clocks is the message bit itself. `g1` and `g2` are 0, so those stages are plain wires. `g3 = 1` inserts the visible XOR in front of `r3`.

For the last 4 clocks the gate opens: feedback is forced to 0 and `r3` shifts out as the remaining parity bits.

## Syndrome and lookup-table correction

Received bits enter at `s0`, `c14` first. Each clock is the same LFSR used as a divider:

```text
fb = s3
s0' = r_i XOR fb
s_k' = s_{k-1} XOR g_k fb
```

After 15 clocks the register holds `s(x) = r(x) mod g(x)`. `0000` means no error.

Error location uses a **lookup table**: compare `S` with `x^i mod g(x)` for `i = 0..14`. The matching index is the erroneous bit. Flip that bit, then recover the systematic payload `c4..c14`.

## Relationship to hardware

- **Message cells:** the eleven editable input boxes hold `m0`–`m10`.
- **Encoder flip-flops `r0`–`r3`:** the remainder register after premultiplication by `x^4`.
- **XOR taps:** exactly the nonzero coefficients of `g(x)` other than `x^4`. Changing `G` in `src/code.zig` moves both the math and the drawing.
- **Gate:** after 11 clocks the feedback XOR is disconnected so the remainder can shift out.
- **Channel switch:** selecting `c_i` models an inverter on that transmitted wire.
- **Syndrome flip-flops `s0`–`s3`:** hardware division of the received polynomial by `g(x)`.
- **Lookup table:** matches the syndrome against the 15 nonzero columns of the cyclic parity-check structure.

This simulator supports no error or one injected error. The (15,11) Hamming cyclic code corrects any single-bit error; it does not guarantee correction of multiple simultaneous errors.

## Suggested demonstration

1. Enter `10110011101` and step the encoder clock by clock until the four check bits appear.
2. Transmit with no error. Clock the syndrome register and show that it finishes at `0000`.
3. Reset, encode the same message, and inject an error at `c0` (near the beginning), `c7` (middle), and `c14` (end). In each case the syndrome is nonzero, the lookup table names the injected bit, and the recovered message is `10110011101`.
4. Press `t` and show the table of all 15 error locations and their syndromes.
5. Explain that the XOR in front of `r3`/`s3` is there because `g3 = 1`, while `r1` and `r2` are plain shift stages because `g1 = g2 = 0`.
